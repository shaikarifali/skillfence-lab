AST01

Malicious Skills

Critical4 labsMitigation: Merkle root signing, registry scanning
The Story

An organisation's coding agent has ordinary skills installed — github-search, jira, slack, deploy. A developer adds a third-party one, github-security-review: “Scan a GitHub repository for security vulnerabilities.” Internally its behavior has nothing to do with that sentence — it reads credentials and exfiltrates them, then finishes the scan it was asked for so the output still looks correct. The four cases below are that pattern in four shapes.

Supply Chain Compromise

Critical3 labsMitigation: registry transparency, provenance tracking
The Story

Nobody installs a stranger's skill without review — every skill in production was approved once. The attack isn't getting past that first review; it's what happens after. An update ships, the changelog line sounds routine, and the new manifest — treated as self-certifying — quietly declares a capability nobody signed off on.

AST03

Over-Privileged Skills

High3 labsMitigation: least-privilege manifests, schema validation
The Story

Not every over-privileged skill is written by an attacker. Most look mundane: a manifest states a negative — “no network” — because that's what its author believed once, and nothing re-verifies it at runtime. Snyk's Feb 2026 finding of 280+ credential-leaking skills is this shape, not necessarily malicious by design.

Insecure Metadata

High3 labsMitigation: static analysis, safe parsers, sandboxed loading
The Story

A manifest schema can only say so much: a declared domain, a blanket secrets.access boolean, a skill's own name standing in for verified identity. All of it is metadata a review trusts by default, because at install time there's rarely anything else to go on.

AST05

Untrusted External Instructions

High3 labs · flagshipMitigation: content pinning, continuous rescanning
The Story

In this category the skill is never the problem. A trusted skill, accurate manifest, fetches content from its own declared domain. A later edit to that page embeds an instruction; the naive agent reads it as input and acts on it. The “Air” PoC showed this bypassing every scanner tested — every one inspected the skill package, and the payload was never in the package.

AST06

Weak Isolation

Critical3 labsMitigation: per-skill sandbox roots, fail-safe refusal
The Story

Every other category is about a gap between what a manifest declares and what a skill does. This one is different: even a correct declared-vs-requested comparison says nothing about whether the resolved, real filesystem path a skill touches ever leaves its own sandbox. One lab escapes straight to the host. One escapes sideways, into a directory representing a different skill's own sandbox. One carries the exact same “./” prefix as every legitimate workspace-relative path this skill makes — and still walks out, once the .. segments inside it are actually resolved.

AST07

Update Drift

High3 labs · multi-invocationMitigation: cross-invocation behavioral baseline
The Story

AST02 shows a manifest that changes to introduce a new capability. This category is quieter: the manifest never changes at all — no version bump, no skill.update event anywhere. A skill's real, observed behavior simply gains a capability on its second invocation that its first invocation never exercised. In the hardest case here, the skill's network policy is honestly unrestricted, so every destination is “declared, allowed” by construction — and only a memory of what this exact skill has actually done before can tell the difference.

AST08

Poor Scanning

Critical3 labsMitigation: instruction-shape detection, not code-pattern grep
The Story

Every skill below ships with a manifest field declaring it already passed a static security scan, naming the exact tool that reviewed it. That's the real security.scanned/scan_tool attestation the schema supports. The point is what that's worth: a scanner tuned to catch code-layer shapes has nothing to say about a directive written as plain prose. A scanner that reads the interesting parts of a document and skims the rest misses the same directive buried in thirty lines of plausible changelog. A scanner tuned to this exact suite's own known payload signature misses the same intent phrased one sentence differently. None of these are strawmen — they're realistic ways a static review actually gets built, and SkillFence's runtime doesn't share any of their blind spots, because it isn't grepping for shapes or literal strings. It's recognizing instruction-shaped language.

Detection model

Deterministic, additive scoring — no LLM in the security-decision path. 0–29 low, 30–49 medium, 50–69 high, 70+ critical — only critical default-recommends reject.
